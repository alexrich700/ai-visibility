# SEO Audit Pipeline — Architecture v2.1

## What Changed & Why

**Old approach:** 16-tab Excel workbook with educational sales tabs, raw Ahrefs backlink dumps (2000 rows each), and data overload. The audit told the truth but overwhelmed clients.

**New approach:** A story-driven web dashboard on the existing Replit app (Node + React) with magic-link sharing and Present Mode. Built around one narrative: *"Your competitors are winning. Here's how we catch them."* Every section maps to that story arc. Data serves the narrative, not the other way around.

**Key principles:**
1. Open with competitive pain (geo grids, SERP gaps)
2. Show the "red sea" (what's missing, visually)
3. Quantify the opportunity (leads, revenue)
4. Present the investment (phased deliverables with hours)
5. Never show more than a client can absorb in one sitting

**Resolved decisions:**
- Dashboard lives on existing Replit app domain
- Magic-link sharing (existing token-based access) for client view
- No white-labeling needed
- One-time sales tool (not recurring tracking)
- Google Ads projection stays (powered by Keyword Planner API)
- GEO visibility section already built (Gemini + OpenAI) — keep as-is
- Geo grids built with DataForSEO (not Local Viking)
- Keyword research moves to Google Ads Keyword Planner API

## Keyword Research: Google Ads Keyword Planner API

### Why Switch from DataForSEO Keywords

Google Ads Keyword Planner API is the authoritative source for Google search volume data and **costs $0 per API call** (no per-call charges). DataForSEO pulls from this same source with a middleman markup and lag. For a pipeline that also runs Google Ads projections, using Keyword Planner directly means one data source for both SEO keyword research and PPC forecasting.

### What the Keyword Planner API Provides

**GenerateKeywordIdeas endpoint:**
- Seed with keywords, URLs, or both
- Filter by geo (city, DMA, zip code, region) using geo target criterion IDs
- Returns: search volume, CPC, competition level, seasonal trends
- Up to 250,000 keyword ideas per URL seed
- Supports language filtering

**GenerateHistoricalMetrics endpoint:**
- Historical monthly search data for specific keywords
- Geo-filtered volume (not just national averages)
- 12-month trend data

**GenerateForecastMetrics endpoint:**
- Projected clicks, impressions, cost, conversions per keyword
- Geo-specific CPC estimates
- This powers the Google Ads Projection section directly

### Practical Implementation for a Local Service Business

**Example: Roofer in Austin, TX servicing 10 surrounding cities**

```
Step 1: Seed keyword ideas
  POST GenerateKeywordIdeas
  - seed_keywords: ["roofer", "roof repair", "roof replacement", "roofing company"]
  - url_seed: "https://clientsite.com" (optional, pulls from their site)
  - geo_targets: [Austin DMA criterion ID]
  - language: "en"
  → Returns: 100-500 keyword ideas with volumes

Step 2: Get geo-specific volumes for top keywords
  POST GenerateHistoricalMetrics
  - keywords: [top 50-100 from step 1]
  - geo_targets: [Austin city ID]  (then repeat for each service city)
  → Returns: monthly volumes per keyword per city

Step 3: Run PPC forecast
  POST GenerateForecastMetrics
  - keywords: [top commercial-intent keywords]
  - geo_targets: [service area]
  - date_range: next 90 days
  → Returns: clicks, impressions, CPC, conversions, cost
  → Powers the Google Ads Projection section
```

**Approach for multi-city businesses:**
- Option A: One DMA-level call for broad keyword discovery, then city-specific calls for volume data on top keywords
- Option B: Separate calls per city for full granularity
- Recommendation: Hybrid — DMA for discovery, top 6 cities individually for volume comparison

### Access Requirements

- Active Google Ads manager account (MCC)
- Developer token (from API Center in Google Ads)
- OAuth 2.0 authentication
- Standard Access level for unlimited operations (Basic = 15,000 ops/day)
- **No minimum spend requirement** for API access itself
- Volume data may be bucketed (80 logarithmic ranges) for low-spend accounts — supplement with DataForSEO's proprietary volume metric for precision on lower-volume keywords

### Node.js Implementation

No official Google Ads API client for Node.js. Options:
1. **`google-ads-api` npm package** — Most popular community library
2. **Direct REST API calls** — Google's recommended approach for Node.js
3. Authenticate via OAuth 2.0 with `googleapis` npm package

## Geo Grid Architecture: DataForSEO Build

### Decision: Build Custom with DataForSEO

**Why not Local Viking:**
- Local Viking's API is limited/poorly documented — primarily a platform tool, not an API-first product
- Subscription pricing ($149/month Agency) is expensive for one-time audit grids
- Can't embed their visualization in your dashboard
- Credit system is opaque

**Why not Local Falcon:**
- Better API than Local Viking, but still $50-100/month subscription
- Fixed grid sizes only (can't do custom spacing)
- Per-credit pricing ($0.0033/credit) is 5x more expensive than DataForSEO

**Why DataForSEO:**
- You're already using it for everything else
- Cheapest per-grid cost by far
- Full control over grid size, spacing, and visualization
- Custom Leaflet.js map embedded directly in your dashboard
- You calculate SoLV and avg rank yourself (simple math)

### Cost Comparison

|-----------|----------|----------------------|----------------------|--------------|-------------|
| 7×7 (49 pts) | 5 | **$0.15** | $0.29 | $0.81 | ~$5-10 (est.) |
| 13×13 (169 pts) | 5 | **$0.51** | $1.01 | $2.79 | ~$15-25 (est.) |

**Keyword Selection Logic:**
1. After keyword research completes (Step 3), auto-rank keywords by search volume
2. Pre-select top 3 highest-volume keywords (default)
3. Allow specialist to select up to 5 (hard cap for cost control)
4. Show estimated cost and processing time before running
5. For national businesses: skip geo grid entirely

**Grid Defaults:**
- Local businesses: 13×13 grid, 1 mile spacing (covers ~13 mile radius)
- Metro businesses: 13×13 grid, 2 mile spacing (covers ~26 mile radius)
- Rural businesses: 7×7 grid, 3 mile spacing (covers ~21 mile radius)
- Max: 5 keywords per grid (hard limit in UI)

### Building the Grid: Technical Implementation

**Step 1: Calculate coordinates**
```javascript
// Haversine-based grid point calculation
function generateGridPoints(centerLat, centerLng, gridSize, spacingMiles) {
  const points = [];
  const halfGrid = Math.floor(gridSize / 2);
  const spacingDeg = spacingMiles / 69.0; // rough deg per mile
  const spacingLngDeg = spacingMiles / (69.0 * Math.cos(centerLat * Math.PI / 180));

  for (let row = -halfGrid; row <= halfGrid; row++) {
    for (let col = -halfGrid; col <= halfGrid; col++) {
      points.push({
        lat: centerLat + (row * spacingDeg),
        lng: centerLng + (col * spacingLngDeg),
        row, col
      });
    }
  }
  return points; // 169 points for 13×13
}
```

**Step 2: Batch API calls**
- DataForSEO accepts up to 100 tasks per POST request
- For 13×13 (169 points) × 1 keyword: 2 POST requests
- For 13×13 × 5 keywords: 9 POST requests (can run in parallel)
- Standard queue: results in ~5-30 seconds
- Priority queue: results in ~1 minute

**Step 3: Calculate metrics**
```javascript
function calculateGridMetrics(results, clientBusinessName) {
  const totalPoints = results.length;
  let inTop3 = 0;
  let totalRank = 0;
  let rankedPoints = 0;

  results.forEach(point => {
    const rank = findBusinessRank(point.items, clientBusinessName);
    point.rank = rank; // null if not found
    if (rank && rank <= 3) inTop3++;
    if (rank && rank <= 20) { totalRank += rank; rankedPoints++; }
  });

  return {
    shareOfLocalVoice: (inTop3 / totalPoints * 100).toFixed(1), // e.g., "50.3%"
    averageGridRank: rankedPoints > 0 ? (totalRank / rankedPoints).toFixed(1) : "N/A",
    visiblePoints: rankedPoints,
    totalPoints,
    top3Points: inTop3
  };
}
```

**Step 4: Render with Leaflet.js**
- Circle markers at each grid point
- Color scale: Green (#1-3) → Yellow (#4-7) → Orange (#8-10) → Red (#11-20) → Gray (not found)
- Click a point → popover shows full local pack results at that location
- Toggle between keywords
- Show SoLV and Avg Rank as overlay stats

## Dashboard Sections (The "Views")

The dashboard follows a presentation story arc. Each section answers one question a business owner cares about.

### Section 1: Competitive Snapshot (First Thing They See)

**What the client sees:**
- Side-by-side comparison: Client vs 2-3 top competitors
- Metrics: Domain Rating, organic keywords, monthly traffic, Google reviews (count + rating), GBP completeness
- Simple bar chart per metric
- A single "Market Position" score (composite, 0-100)
- One-line verdict: "You're currently #4 of 4 in your local market for online visibility"

**Data sources:** DataForSEO (`ranked_keywords`, `domain_rank_overview`, `backlinks_summary`) + Google Places API

**LLM usage:** None. Pure data.

---

### Section 2: Geo Grid — Local Map Pack Visibility

**What the client sees:**
- Interactive Leaflet.js map with color-coded grid points (configurable 7×7 to 15×15)
- Each point shows ranking position (1-20 or "Not Found")
- Color scale: Green (#1-3), Yellow (#4-7), Orange (#8-10), Red (#11-20), Gray (Not found)
- Toggle between up to 5 primary keywords
- Summary stats: SoLV ("You appear in the 3-pack in 85 of 169 locations — 50.3% Share of Local Voice") + Average Grid Rank
- Side-by-side: Client grid vs top competitor grid

**Data sources:** DataForSEO Google Maps SERP API (169 points × 3-5 keywords = $0.30-0.51 per grid set)

**LLM usage:** None. Pure data + visualization.

---

### Section 3: AI/GEO Visibility — The New Frontier

**What the client sees:**

### Section 4: Keyword Rankings & Organic Gaps (The "Red Sea")

**What the client sees:**

- Summary: "You rank in the top 10 for 4 of 72 target keyword combinations"

**Data sources:** DataForSEO SERP API + Google Ads Keyword Planner (volumes)

**Design rule:** Max 6 columns. First view = 6 highest-opportunity cities.

## Presentation Design Rules

1. **First screen = competitor comparison.** "Here's who's beating you."
2. **Geo grids before data tables.** Visual maps > spreadsheets.
3. **Max 6 columns in any table.** Paginate beyond. Red sea works at 6 wide.
4. **Red = missing, Green = present.** Binary for client view.
5. **Every section ends with one sentence:** "This means [business impact]."
6. **Revenue > traffic.** "$40K/month in lost revenue" > "4,000 monthly searches."
7. **3 competitors max.** More = hopeless. 3 = motivated.
8. **GEO screenshots.** Show what AI says about their competitor.
9. **Action plan = the proposal.** The audit IS the close.

## Remaining Open Questions

1. **Grid size default for the UI:** Default to 13×13 with 1-mile spacing? Or let the specialist choose? The onboarding flow above suggests a choice but defaults to 13×13.
2. **Keyword cap for geo grids:** Hard cap at 5? Or allow more with a cost warning? At 5 keywords × 169 points, that's 845 API calls (~$0.51). At 10 keywords, that doubles to ~$1.01.
3. **Competitor auto-detection for geo grids:** Should the geo grid automatically show the top competitor's SoLV alongside the client's? This doubles the API cost per grid but is the most visually compelling comparison.
4. **National business handling:** Skip geo grid and local pack entirely? Or offer a national organic rankings view instead?
5. **Onboarding flow location:** Is the specialist-facing onboarding (keyword selection, grid config) a separate admin view, or part of the audit creation wizard in the existing app?
